# company_prompt

케어캠프 **클로드 초급 과정(1~5교시, 무료 계정 기준)**의 실습 자산 저장소입니다.
수강생이 쓰는 **프롬프트 라이브러리**와, 교육 대상 기업에 맞춰 그 프롬프트의 빈칸을 채워 주는 **기업 맞춤 프롬프트 키트 스킬**을 함께 관리합니다.

---

## 무엇이 들어 있나

| 파일 | 역할 | 쓰는 사람 |
|---|---|---|
| `index.html` | 프롬프트 라이브러리 — 53개 프롬프트를 교시별로 모아 둔 단일 HTML 페이지 | **수강생** (수업 중·수업 후) |
| `SKILL.md` | 기업 맞춤 프롬프트 키트 스킬 — 기업명을 받아 빈칸을 채운 프롬프트 세트를 생성 | **강사** (수업 준비) |
| `references/library-registry.md` | 번호·실습 코드·한도의 **단일 기준**. 스킬이 조립·검증할 때 대조하는 표 | 스킬이 참조 |

두 자산은 **같은 번호 체계**를 씁니다. 라이브러리를 고치면 레지스트리도 함께 고쳐야 합니다.

```
사람이 보는 것        index.html  ──┐
                                    ├── 같은 번호 체계 (1~53)
스킬이 참조하는 것     references/library-registry.md ──┘
                              ↑
                        SKILL.md 가 조립·검증에 사용
```

## 1. 프롬프트 라이브러리 (`index.html`)

브라우저로 바로 열리는 단일 파일입니다. 빌드 과정이 없습니다.

- **교시별 구분** — 1교시 시작하기 / 2교시 에이전트 이해 / 3교시 코워크 / 4교시 스킬 / 5교시 터미널
- **유형** — `교안용`(교안에 실린 프롬프트) · `예시용`(실무 확장)
- **용도** — `수업 중 실습`(교시당 3회 제한) · `화면 참고` · `수업 후 활용`
- **실습 코드** — 교안 수록 7개에 `S1-P01` `S1-P02` `실습 1-3` `S2-P01` `S2-P02` `S2-P03` `S3-P01` 표기
- 키워드 검색, 복사 버튼, 교시별 앵커 이동 지원

### 무료 계정 한도 (페이지 상단 배너에도 표시)

| 교시 | 직접 입력 실습 | 파일 생성 |
|---|---|---|
| 1교시 | 3회 (실습 1-1 · 1-2 · 1-3) | 0회 |
| 2교시 | 3회 (실습 2-1 · 2-2 · 2-3) | 0회 |
| 3교시 | 2회 (29 · 30번) | **1인 1회** |
| 4교시 | 2회 (39 · 40번) | 0회 |
| 5교시 | 시연 중심 | 0회 |

반복 연습은 Haiku 4.5 · 노력 낮음, 지시를 정확히 따라야 하는 실습은 Sonnet 5 · 노력 중간을 권장합니다.

## 2. 기업 맞춤 프롬프트 키트 (`SKILL.md`)

교육 대상 기업이 바뀔 때마다 `[주제]`·`[업무 설명]`·`[회의록]` 같은 빈칸을 손으로 채우는 대신,
**기업 이름 하나로** 그 기업 업무에 맞는 재료를 채워 줍니다.

### 설치

이 저장소를 그대로 스킬로 쓸 수 있습니다. `SKILL.md`가 루트에 있고 `references/`가 옆에 있는 구조입니다.

```
company-prompt-kit/
├── SKILL.md
└── references/
    └── library-registry.md
```

### 사용

```
/company-prompt-kit 한빛식품
/company-prompt-kit 한빛식품 영업관리팀, 생산관리팀
```

기업명만 주어도 동작하며, 부서·직무를 함께 주면 직무별로 나눠 생성합니다 (최대 3개).

### 하네스 — 6단계 고정 실행

```
STAGE 0  GATE      입력 확인          → INPUT
STAGE 1  RESEARCH  웹 검색 3종        → FACTS
STAGE 2  PROFILE   회사 프로필 카드   → PROFILE   ★ 이후 모든 재료의 단일 근거
STAGE 3  MATERIAL  재료 생성          → MATERIAL
STAGE 4  ASSEMBLE  완성 프롬프트 조립 → DRAFT
STAGE 5  VERIFY    검증 루프 A~D
STAGE 6  RENDER    최종 출력
```

뒤 단계는 **직전 블록만** 참조합니다. 조사 원문을 다시 끌어오지 않기 때문에 같은 회사로 두 번 돌려도 결과가 흔들리지 않습니다.

### 검증 루프 — 각 최대 2회

| 루프 | 잡는 것 | 실패 시 복귀 |
|---|---|---|
| **A** 번호 정합성 | 레지스트리에 없는 번호, 번호↔제목↔실습코드 불일치 | STAGE 4 |
| **B** 원문 보존 | 교안 문장 변형, 3번의 구버전 사용 | STAGE 4 |
| **C** 안전 | 실제 고객·금액 혼입, 가상 표기 누락, 강사 전용 항목 유출 | STAGE 3 |
| **D** 한도 | 실습 3회 초과, 파일 생성 2회 이상, 턴 추가 | STAGE 3 |

2회 후에도 통과하지 못하면 **그 항목만 제외하고 사유를 남깁니다.** 무한 재시도가 없습니다.

### 출력 형식 A / B

| 형식 | 적용 | 순서 |
|---|---|---|
| **A** | 빈칸을 한 줄로 바꿔 쓰면 되는 항목 (1번) | 완성 예시 → 대괄호 후보 3개 |
| **B** | 빈칸이 데이터 블록·지침 본문인 항목 (3·4·14·15·17·18·19번) | 재료 → 완성 프롬프트 |

## 3. 편집 규칙

이 세 가지는 자산이 서로 어긋나지 않게 하는 최소 규칙입니다.

1. **번호는 레지스트리가 기준입니다.** 라이브러리에 프롬프트를 추가하면 `references/library-registry.md`에도 같은 번호로 등록합니다.
2. **교안 원문 문장은 바꾸지 않습니다.** 레지스트리의 "원문 보존 대상" 번호(1·2·3·4·13~19·29·30·39·40)는 대괄호 빈칸과 지정 데이터 블록만 치환합니다.
3. **직접 입력 실습 개수를 늘리지 않습니다.** 보강은 한 프롬프트의 밀도를 높이는 방향으로만 합니다. 무료 계정 한도 때문입니다.

### 알려진 이력

| 항목 | 내용 |
|---|---|
| 3번 | 라이브러리 구버전("내가 이번 주에 처리한 일")과 교안 S1-P02가 서로 달랐음 → **교안 S1-P02 기준으로 통일 완료** |
| 옛 번호 체계 | 스킬 이전 버전이 쓰던 15개 번호(6=지침 보강, 9=회의록, 12=올린 자료 등) → **폐기.** 현재 53개 연번만 사용 |

## 4. 안전 원칙

라이브러리와 스킬 양쪽에 공통으로 적용됩니다.

- 회의록·실적 자료·명단 샘플은 **전부 가상 예시**입니다. 실제 회사명·고객명·금액은 넣지 않습니다.
- 실제 고객·임직원 정보, 계약 원문, 미공개 재무, 로그인 정보, 사내 주소는 입력 금지입니다.
- 개인 계정 화면과 회사 계정의 메뉴·권한·데이터 정책은 다를 수 있습니다. **관리자 정책이 우선합니다.**
- AI가 만든 숫자·날짜·담당자는 원자료에서 사람이 다시 확인한 뒤 확정합니다.
- 외부 발송·게시·파일 덮어쓰기·자동 실행은 별도 승인 없이 하지 않습니다.
- 강사 시연용 **가상 규정(존재하지 않는 법령)** 은 강사 화면 전용입니다. 수강생 실습 프롬프트로 내보내지 않습니다.

## 참고

교안 자체는 무료 계정 기준으로 작성되었으며, 기능과 화면은 계정·요금제·조직 설정에 따라 달라질 수 있습니다.
